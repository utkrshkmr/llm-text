# Brief: Project 12, Bring up a new open model from its files (book/chapters/ch15_proj_bringup.md {#ch:proj12}, kit code/projects/p12_bringup NEW)

Read projects_common.md first (all of it), then BRIEF_conventions.md (esp. §7), docs/PLAN.md §4 "P12", and the
chapters this capstone of Part II builds on: [@ch:modern], [@ch:anatomy] (incl. its model-files section), [@ch:moe]. Budget on 2×A100-40GB PCIe: ~2 GPU-h (estimate; calibrate in
the GPU stage).

The reader receives only an HF model directory of an architecture the book did not implement (the kit names
candidates of small size, e.g. a recent small dense or MoE release; choose one whose licence permits download and
whose components are reachable from the book's material) and must: read config.json and the safetensors index,
infer the architecture, implement it in llmsys style, load weights (including any packed/quantised layout), match
reference logits (transformers, if installed) to tolerance, produce parameter/FLOP/KV accounting and a memory plan
for the A100, and report surprises. Acceptance (CPU): on a synthetic checkpoint of a "mystery" tiny architecture
generated by the kit (random weights, official-style names), the reader's model reproduces the kit's hidden
reference logits; accounting equals instantiated counts; loader reads only needed tensors.

Deliverables per projects_common.md: chapter (spec framed as research questions, prerequisites, milestones,
baselines, budget table, rubric, extensions, Research frontier), solutions if exercises, kit with reference/,
test_p12_acceptance.py, configs/smoke + configs/full, Makefile, README.

A transformer reads a sequence of tokens and produces one vector per token. In a decoder the mask hides the future, so each position sees only the tokens before it. In an encoder there is no such mask, and every position sees the whole sequence at once. The difference looks small in code, a single triangular matrix of booleans, but it changes what the model can learn and how the model can be served.

A decoder is trained to predict the next token. Every position produces a loss term, so one pass over a batch yields as many gradient signals as there are tokens. An encoder cannot predict the next token, because the next token is already visible. It is trained instead to reconstruct tokens that were hidden or corrupted. Only the corrupted positions produce a loss, so an encoder sees many more tokens than it learns from.

The key and value vectors of a decoder are stored in a cache while a sequence is generated. The cache grows by one entry per layer for every new token, and reading it back is the main cost of a long generation. An encoder has no cache. It processes a complete sequence in one forward pass and then forgets it. The cost of an encoder is therefore pure compute, and the way to use a GPU well is to batch many sequences together.

Padding is the price of batching sequences of different lengths. If a batch holds one long sequence and many short ones, most of the matrix is filled with padding tokens that carry no information but cost the same arithmetic as real tokens. Sorting sequences by length before forming batches keeps similar lengths together and cuts the waste. Packing several short sequences into one row removes the waste entirely, at the cost of a more complicated mask.

A sentence embedding is a single vector that summarizes a whole sequence. The simplest way to build one is to average the token vectors of an encoder. Two sentences with the same meaning should land near each other, and sentences with different meanings should land far apart. A contrastive loss teaches exactly that: every sentence in a batch must find its own paraphrase among all the other sentences, and the other sentences act as negatives for free.

A cross encoder reads the query and the document together as one sequence. Every query token can attend to every document token, which makes the score accurate, but the model must run once for every pair. A bi encoder reads the query and the document separately and compares two vectors. The document vectors can be computed once and stored, so a query costs one forward pass no matter how many documents are searched.

An image can be fed to the same encoder. The picture is cut into square patches, each patch is flattened into a vector, and the vectors are projected to the width of the model. From that point on the transformer does not know whether its tokens came from words or from pixels. Halving the patch size quadruples the number of tokens, and attention cost grows with the square of the token count, so the patch size is a direct lever on the compute budget.

Memory bandwidth is the quantity that decides whether a kernel is fast. A matrix multiply with a small batch reads every weight once and does little arithmetic per byte, so it waits on memory. The same multiply with a large batch reuses every weight many times and waits on the arithmetic units instead. The ratio of arithmetic to bytes is the arithmetic intensity, and the roofline model turns it into a bound on throughput.

Mixed precision stores weights and activations in sixteen bits and accumulates sums in thirty two bits. The smaller format halves the bytes moved and doubles the tensor core rate, while the wide accumulator keeps the sums accurate. Normalization layers and softmax are computed in the wide format because they add many terms of very different magnitude.

A profiler shows where the time goes. Kernels that are small and numerous point to launch overhead, which a compiler can remove by fusing them. Kernels that move many bytes and do little arithmetic point to memory traffic, which a better layout or a fused epilogue can remove. Kernels that are already at the arithmetic peak cannot be made faster by anything but a smaller model or a cheaper algorithm.

Distributed training splits the work over many devices. Data parallelism copies the model and divides the batch, then averages the gradients with an all reduce. Tensor parallelism splits each weight matrix and exchanges activations. Pipeline parallelism assigns whole layers to different devices and passes activations from stage to stage. Each scheme trades a different kind of communication for a different kind of memory saving.
